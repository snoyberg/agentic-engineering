# Upstream and downstream guidance

Repositories may reference this repository without copying it.

A downstream project should generally contain:

1. a reference to the upstream guidance it follows;
2. project-specific rules;
3. explicit deviations where they matter.

Do not copy upstream documents merely to make them local. Duplication makes it difficult to know whether differences are intentional or stale.

When project work reveals a reusable improvement:

- project-specific improvement: keep it local;
- user-specific preference: update the user's guidance;
- broadly useful improvement: propose it upstream;
- genuine philosophical disagreement: document the alternative rather than forcing consensus.

Agents should help classify the change but humans determine where foundational preferences belong.
